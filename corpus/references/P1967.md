# P1967 — `#embed`

## Problem
Embedding a binary asset — a shader, an icon, a hash table, a baked
ML weight file — into a C++ translation unit required either:

- a build-step that produces a `.cpp` file full of `0xNN, 0xNN, …`
  literals (slow to compile, hard to update from the editor);
- platform-specific tricks like `objcopy --add-section` or
  `incbin` linker scripts (non-portable, hostile to cross-compilation);
- a `std::ifstream` runtime load (no longer compile-time data,
  and breaks the "freestanding-compatible" requirement).

`#embed` is a *preprocessor* directive — like `#include` — that splices
the bytes of a file into the translation unit as an
*integer-constant-expression initializer list*.

## Key syntax

```c
#embed "path"                              // splice the bytes
#embed <path>                              // search standard paths
#embed "path" if_empty(0)                  // value if file is empty
#embed "path" limit(N)                     // first N bytes only
#embed "path" prefix(0xDE, 0xAD)           // splice prefix bytes first
#embed "path" suffix(0xBE, 0xEF)           // append suffix bytes
__has_embed("path")                        // preprocessor predicate
```

Each byte is spliced as a value of type `unsigned char` (0-255). The
result is a comma-separated initialiser list, suitable for any
aggregate initialiser context.

## Canonical example

```cpp
inline constexpr std::array<unsigned char, /* size deduced */ > kIcon = {
    #embed "assets/icon.png"
};

static_assert(kIcon.size() > 0);

// Or as a string view, if the asset is textual:
inline constexpr char kShader[] = {
    #embed "assets/shader.glsl"
    , 0           // NUL-terminate (since #embed doesn't add one)
};
```

## Canonical example: conditional inclusion

```cpp
#if __has_embed("config/release_key.bin")
inline constexpr unsigned char kReleaseKey[] = {
    #embed "config/release_key.bin"
};
#else
inline constexpr unsigned char kReleaseKey[] = {/* fallback */};
#endif
```

## Pre-C++26 equivalent

```cpp
// pre-build step generates icon_bytes.h:
//   inline constexpr unsigned char icon_bytes[] = { 0x89,0x50,0x4E,... };
#include "icon_bytes.h"

// or runtime load (loses constexpr-ness):
auto load_icon() {
    std::ifstream f("assets/icon.png", std::ios::binary);
    return std::vector<unsigned char>(std::istreambuf_iterator<char>(f), {});
}
```

The pre-build path is portable but adds a code-generation step and
breaks if the asset is updated without rerunning the generator. The
runtime path costs a file-system dependency and forfeits compile-time
checking.

## Gotchas

- `#embed` is *preprocessor* level — it cannot reference C++ template
  parameters or constexpr values. The path is a string literal,
  evaluated by the preprocessor, before any template instantiation.
- The resulting initialiser list contains only byte values — there is
  no automatic NUL terminator for textual files. Add one explicitly
  if you need a `const char*`-shaped result.
- Asset paths are resolved with the same lookup rules as `#include`,
  including `-I` (or `/I`) paths. Compiler-specific search orders
  apply; use `#embed <path>` for system-style lookup.
- Very large embeds can stress the preprocessor; some implementations
  fall back to a binary intermediate to keep tokeniser memory bounded.
