# P2169 — A nice placeholder with no name

## Problem
C++ has long needed a way to say "I am binding this thing because the
grammar requires me to, but I don't intend to use it". The historical
patches:

- `[[maybe_unused]] auto x = …` — suppresses the warning but still
  introduces the name `x`.
- `(void)x;` — suppresses use-of-x warnings post-binding.
- A structured binding where you don't want some members: `auto [_, y]
  = pair;` happened to work because `_` was a legal identifier, but
  *only one* `_` per scope (declaring two re-declares the same name).

P2169 makes `_` (a single underscore) a *placeholder name*. Multiple
`_` declarations in the same scope are allowed; each refers to a
distinct, unnamed binding. The placeholder cannot be referenced
(no expression `_;` succeeds). Compilers must not warn about
unused `_` declarations.

## Key syntax

```cpp
auto _ = expensive_call_returning_unused_value();  // OK, no warning
auto [_, y, _] = std::tuple{1, 2, 3};              // bind only y; the two _ are independent
for (auto _ : ints) ++count;                       // count occurrences, ignore values
```

The placeholder works in:

- variable declarations
- structured bindings (any number of `_`)
- range-for bindings
- lambda init-capture (`[_ = make_guard()]`)
- function parameter lists (`void f(int, int _)`)

## Canonical example: unused structured-binding pieces

```cpp
std::tuple<int, std::string, double> get_record();

void process() {
    auto [id, _, score] = get_record();   // we only need id and score
    use(id, score);
}
```

## Canonical example: RAII guard

```cpp
void critical_section() {
    auto _ = std::scoped_lock{mtx};       // hold the lock for this scope
    do_work();
}                                          // _ destroyed → lock released
```

## Pre-C++26 equivalent

```cpp
// 1. Named placeholder + suppress warning.
auto [id, name_unused, score] = get_record();
(void)name_unused;

// 2. Single-underscore trick (fragile; only one per scope).
auto [id, _, score] = get_record();
// auto _ = std::scoped_lock{mtx};        // ERROR: redeclaration of '_'
```

The trick of using `_` worked accidentally — exactly one in scope.
P2169 formalises it: any number, no warnings, no reference.

## Gotchas

- A single underscore name in *older* code may have been a real
  identifier. The compatibility rule: if any prior `_` in the same
  scope refers to a normal variable, P2169 placeholders still work,
  but you cannot reference the placeholder by name (so the
  pre-existing `_` is shadowed only when referenced).
- Multiple `_` placeholders are *distinct objects*. They each have
  their own destruction at scope end. Ordering follows declaration
  order, like any other locals.
- Capturing `_` by reference doesn't make sense — you can't refer to
  it. Use `[_ = …]` (init-capture) to bind a side-effecting value
  whose destruction matters.
