# P0843 — `std::inplace_vector`

## Problem
A `std::vector` allocates on the heap. For a great many real-world
use cases — small bounded queues, embedded systems, RT-deadline
loops, freestanding code — heap allocation is either forbidden or
prohibitively expensive. The community workarounds:

- `boost::container::static_vector<T, N>` — well-known, but
  non-standard.
- `etl::vector<T, N>` — fork-of-STL targeting embedded.
- `std::array<T, N>` + a `size_t size_` member — no inserts/erases,
  default-constructs every slot.
- Hand-rolled `union { T data[N]; }` + placement-new — easy to get
  wrong, every project rewrites it.

`std::inplace_vector<T, N>` is exactly the missing standard form:
a vector-like sequence container with `std::vector`'s API, fixed
capacity `N`, storage in-place (no heap), and *no default-construction*
of unused slots.

## Key syntax

`std::inplace_vector<T, N>` lives in `<inplace_vector>`.

- Constructor surface mirrors `std::vector`'s.
- `push_back` / `emplace_back` throw `std::bad_alloc` (or call the
  hardening handler under [[P3471]]) on overflow.
- `try_push_back` / `try_emplace_back` are *noexcept* and return
  `nullptr` on overflow — embedded-friendly alternatives.
- `static constexpr size_type capacity() noexcept { return N; }`

## Canonical example

```cpp
#include <inplace_vector>

void route_packets(std::span<const Packet> in) {
    std::inplace_vector<Packet, 64> batch;   // no heap; all on stack
    for (const auto& p : in) {
        if (batch.size() == batch.capacity()) {
            send(batch);
            batch.clear();
        }
        batch.push_back(p);
    }
    if (!batch.empty()) send(batch);
}
```

## Canonical example: noexcept push for embedded

```cpp
#include <inplace_vector>

class Mailbox {
    std::inplace_vector<Message, 16> queue;
public:
    bool offer(Message m) noexcept {
        return queue.try_push_back(std::move(m)) != nullptr;
    }
};
```

## Pre-C++26 equivalent

```cpp
// Pick one:
#include <boost/container/static_vector.hpp>
boost::container::static_vector<T, N> v;

// Or:
#include <etl/vector.h>
etl::vector<T, N> v;

// Or hand-roll:
template <class T, size_t N>
class my_static_vector {
    alignas(T) std::byte storage_[sizeof(T) * N];
    size_t size_ = 0;
    // ... 200+ lines of careful placement-new / move / destroy ...
};
```

Each works in its niche. None is portable. P0843 makes the standard
case standard.

## Gotchas

- `inplace_vector::iterator` invalidation rules differ slightly
  from `std::vector` (no reallocation possible, so insert/erase
  invalidate iterators *to elements at or after* the change but
  not earlier elements).
- `sizeof(std::inplace_vector<T, N>)` is roughly `N * sizeof(T) +
  size_member`. Large `N` means large objects; avoid passing by
  value if `N` is non-trivial.
- The element type `T` need not be default-constructible; storage
  is uninitialised until `push_back`. (Contrast with `std::array<T, N>`
  which default-constructs every slot.)
- `try_push_back` returning `nullptr` is the *only* non-throwing
  failure mode; using `push_back` on a full container throws under
  default semantics. Pick the API matching your error model.
