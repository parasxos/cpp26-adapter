# P2662 — Pack indexing

## Problem
Picking the *N*-th element out of a parameter pack required either
`std::get<N>(std::forward_as_tuple(args...))`, a recursive template
that walks the pack, or an obscure two-step using `std::tuple_element`.
All three are clumsy for what is conceptually a one-character subscript.

Pack indexing adds the natural syntax: `Pack...[N]` for a pack of
*values* and `Ts...[N]` for a pack of *types*.

## Key syntax

- `args...[I]` — the `I`-th element of a value pack `args`.
- `Ts...[I]` — the `I`-th type of a type pack `Ts`.
- `I` must be a constant expression in `[0, sizeof...(args))`.

The syntax binds tighter than most operators — parenthesise when in
doubt: `(args...[I]).member` is fine; `args...[I].member` is ambiguous
to readers.

## Canonical example: first / last element

```cpp
template <typename... Ts>
constexpr auto first(Ts... ts) { return ts...[0]; }

template <typename... Ts>
constexpr auto last(Ts... ts) { return ts...[sizeof...(ts) - 1]; }

static_assert(first(1, 2, 3) == 1);
static_assert(last(1, 2, 3) == 3);
```

## Canonical example: type-pack indexing

```cpp
template <typename... Ts>
struct nth {
    template <std::size_t I>
    using type = Ts...[I];
};

static_assert(std::same_as<nth<int, float, char>::type<1>, float>);
```

## Pre-C++26 equivalent

```cpp
template <typename... Ts>
constexpr auto first_v1(Ts... ts) {
    return std::get<0>(std::forward_as_tuple(ts...));
}

template <std::size_t I, typename... Ts>
using nth_t = std::tuple_element_t<I, std::tuple<Ts...>>;
```

Both forms work, but they detour through `std::tuple` solely for the
indexing operation — a runtime/codegen cost (for values) and a layer of
template machinery (for types) that pack indexing makes unnecessary.

## Gotchas

- The index must be a constant expression; you cannot subscript a pack
  with a runtime index.
- Inside a template, the parser needs to know that `args...[I]` is
  pack indexing rather than `args...` followed by `[I]`. In practice
  the compiler disambiguates; if it doesn't, parenthesise.
- Pack indexing does *not* short-circuit instantiation — the entire
  pack must be a valid expression sequence, even if you only index
  one element. If element K is ill-formed, `args...[0]` is still a
  hard error.
