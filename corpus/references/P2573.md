# P2573 — `= delete("reason")`

## Problem
`= delete;` removes an overload from consideration but tells the user
nothing about *why*. The resulting compiler diagnostic is generic
("call to deleted function"), forcing the reader to grep the header
for a comment that may or may not exist. Library authors commonly work
around this by adding a `static_assert(false, "explanation")` inside an
unconstrained overload — but that detection ladder only fires for
overloads, not constructors, and bloats the surface.

C++26 lets you attach a string literal to a deleted declaration, and
the compiler is required to surface it in the diagnostic.

## Key syntax

```cpp
ReturnType fn(Args...) = delete("explain why");
```

The string operand is a string literal (no concatenation across
translation units; pure literal text). It is reported verbatim in the
diagnostic produced when overload resolution selects the deleted
declaration.

## Canonical example

```cpp
struct NotCopyable {
    NotCopyable() = default;
    NotCopyable(const NotCopyable&) =
        delete("NotCopyable owns a unique resource; "
               "use std::move or pass by reference");
    NotCopyable(NotCopyable&&) = default;
};

void use(NotCopyable n);

void caller() {
    NotCopyable n;
    use(n);   // diagnostic includes the reason string
}
```

## Canonical example: removing a dangerous overload

```cpp
namespace dsl {
    // Force callers to spell the unit explicitly.
    void sleep(int seconds);
    void sleep(double) = delete("dsl::sleep takes whole seconds; "
                                "use sleep_ms for milliseconds");
}

void f() {
    dsl::sleep(0.5);   // diagnostic surfaces the suggestion
}
```

## Pre-C++26 equivalent

```cpp
struct NotCopyable {
    NotCopyable(const NotCopyable&) = delete;  // why? a comment somewhere
};

// Or the static_assert ladder (templates only):
template <typename T>
void take(T) {
    static_assert(!std::is_same_v<T, double>,
                  "dsl::sleep takes whole seconds");
}
```

The pre-C++26 path: (1) requires the user to find the comment; (2)
`static_assert(false, …)` workarounds only apply to templates; (3)
diagnostics from a vanilla `= delete` give no actionable text.

## Gotchas

- The reason string is part of the *declaration*, not the *type*.
  Different translation units must spell the reason identically when
  declaring the same deleted function — otherwise you risk ODR.
- Reasons do not appear in `nm` output, debug info, or ABI symbols;
  this is purely compile-time diagnostic sugar.
- A reason on a `default`-ed member has no effect — the compiler will
  reject the syntax.
