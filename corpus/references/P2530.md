# P2530 — Hazard pointers

## Problem
Lock-free reads from a concurrent data structure must not free a node
while a reader is dereferencing it. The reader has no lock; the writer
that removed the node has no synchronous way to wait. Real-world
solutions to this *safe memory reclamation* (SMR) problem split into
two families: epoch-based reclamation (used by RCU, [[P2545]]) and
*hazard pointers*.

Hazard pointers give each reader a small, fixed set of *protected*
slots into which it publishes the address it is currently reading.
A writer wishing to free a node first scans every reader's slots; if
the node appears in any slot, the writer defers the free. Otherwise
the free is safe.

C++26 standardises the hazard-pointer machinery as `std::hazard_pointer`
and its companion CRTP base `std::hazard_pointer_obj_base`.

## Key syntax

- `std::hazard_pointer_obj_base<T>` — CRTP base for objects whose
  storage is reclaimed via hazard pointers. Provides `retire()`.
- `std::hazard_pointer` — RAII handle owning one hazard slot.
- `std::make_hazard_pointer()` — factory.
- `hp.protect(atomic_ptr)` — publishes the address, retries until the
  atomic load is stable, returns the protected pointer.
- `obj.retire()` — request asynchronous reclamation when no hazard
  protects `obj`.

## Canonical example: protected read

```cpp
#include <hazard_pointer>

struct Node : std::hazard_pointer_obj_base<Node> {
    int value;
    Node* next;
};

std::atomic<Node*> head;

int read_head() {
    auto hp = std::make_hazard_pointer();
    Node* p = hp.protect(head);     // safe: hp protects p from retirement
    return p ? p->value : -1;
}

void update(int v) {
    Node* fresh = new Node{v, head.load()};
    while (!head.compare_exchange_weak(fresh->next, fresh)) {}
    if (Node* old = fresh->next) {
        old->retire();              // freed once no hazard pointer holds it
    }
}
```

## Pre-C++26 equivalent

Roll your own (folly, Tbb, libcds) or rely on garbage-collected
languages.

```cpp
// e.g., folly::hazptr_obj_base / folly::hazptr_holder
struct Node : folly::hazptr_obj_base<Node> { /* ... */ };
folly::hazptr_holder hp;
Node* p = hp.get_protected(head);
```

`folly::hazptr` is the most widely-deployed third-party implementation;
P2530 is essentially its standardised form.

## Gotchas

- Hazard pointers protect *one* address per `hazard_pointer` object.
  Reading two atomics requires two hazards (or a `hazard_pointer_array`
  for batch acquisition).
- `retire()` is *asynchronous*: the destructor may run on any thread
  later. Don't depend on per-thread destruction order.
- A bug in any reader (forgetting to release the hazard) leaks
  reclamation indefinitely. Use the RAII handle, don't manually
  publish and forget.
- Tearing on `head.load()` between `protect` and the retry loop
  inside `protect` is handled by the implementation; user code does
  not need to retry.
