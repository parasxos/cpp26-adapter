# P2900 — Contracts for C++

## Problem
`assert(cond)` from `<cassert>` is the only contract-checking primitive
in pre-C++26 C++, and it has fundamental defects:

- It is removed by `NDEBUG`, so a release build silently disables every
  check rather than letting the program decide.
- It does not distinguish *preconditions*, *postconditions*, and
  *in-body assertions* — all three are the same macro.
- It cannot bind the result of a function (no postcondition can
  reference the return value naturally).
- Violations call `abort()` immediately, with no opportunity to log,
  collect telemetry, or escape.

C++26 introduces three contract-checking constructs with a uniform
*evaluation semantic* selected by the build configuration, plus a
user-overridable *violation handler*.

## Key syntax

- `pre(cond)` — function precondition; placed after the parameter list,
  before the body or `noexcept`/`requires`.
- `post(name : cond)` — function postcondition; `name` binds the
  return value inside `cond`.
- `contract_assert(cond)` — in-body assertion (replaces `assert`).

Evaluation semantic (chosen by the build, not by the source):

| Semantic | Meaning |
|---|---|
| `ignore` | predicate not evaluated (build-time opt-out) |
| `observe` | predicate evaluated; on failure, handler called and execution continues |
| `enforce` | predicate evaluated; on failure, handler called and (by default) `std::terminate()` |
| `quick-enforce` | predicate evaluated; on failure, immediate trap |

Violation handler:

- `std::contracts::contract_violation` — the violation type passed to
  the handler (location, predicate text, kind, detection mode, …).
- `std::contracts::invoke_default_contract_violation_handler(v)` —
  callable to invoke the default handler.

## Canonical example

```cpp
#include <contracts>

int divide(int a, int b)
  pre (b != 0)
  post (r : r * b == a)
{
    contract_assert(a >= 0);
    return a / b;
}

void install_logging_handler() {
    std::contracts::set_contract_violation_handler(
        [](const std::contracts::contract_violation& v) {
            std::print("contract violation: {} at {}:{}\n",
                       v.comment(), v.location().file_name(),
                       v.location().line());
        });
}
```

## Pre-C++26 equivalent

```cpp
#include <cassert>

int divide(int a, int b) {
    assert(b != 0);              // disappears under NDEBUG
    assert(a >= 0);
    int r = a / b;
    assert(r * b == a);          // post — no natural binding
    return r;
}
```

The pre-C++26 form: (1) silently disappears in release builds; (2) gives
no way to log-and-continue; (3) cannot express "post" semantically; (4)
collapses three concepts (pre / assert / post) into one macro.

## Gotchas

- Contract predicates are evaluated in an *evaluation context* that
  forbids side effects from being observed if the predicate is
  `ignore`d at build time — code that *would* mutate state inside a
  contract predicate is ill-formed (or UB at the discretion of the
  semantic).
- `post(r : …)` evaluates *after* destructors of automatic objects in
  the function body. Don't reference a parameter passed by-reference
  if the caller may invalidate it before return.
- The default violation handler calls `std::terminate()`. Replacing it
  globally affects every contract in the translation unit — including
  third-party code linked in.
- Build-mode mismatch across TUs is a silent footgun; use a single
  contract-semantic for the whole binary.
