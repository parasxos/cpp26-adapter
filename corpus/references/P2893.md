# P2893 — Variadic friends

## Problem
A type can declare a *friend* template like `template <typename T>
friend class Manager;`, but it could not declare a *parameter pack* of
friends. Library authors who wanted to befriend "all of `Manager`,
`Worker`, and `Visitor`" had to either repeat the `friend` declaration
or use the access-token pattern (a private nested type passed through
APIs as a proof-of-trust). The latter is unwieldy; the former drifts
out of sync.

P2893 allows `friend Ts...;` and `template <…> friend class Ts;` to
expand a parameter pack of types as friend declarations.

## Key syntax

- Inside a class template, `friend Ts...;` — befriends every type
  in the pack `Ts`.
- The friend declaration must appear in a class scope; the pack
  must be in scope.
- Templated forms (`friend class Ts...`) and value-template forms
  (`template <auto V> friend void f();`) compose the same way.

## Canonical example

```cpp
template <typename... Plugins>
class Engine {
    int internal_state_ = 0;

    // Every plugin type may touch internal_state_.
    friend Plugins...;

public:
    template <typename Plugin>
    void install() {
        Plugin::activate(*this);
    }
};

struct AuditPlugin {
    static void activate(Engine<AuditPlugin>& e) {
        ++e.internal_state_;            // access granted by variadic friend
    }
};

struct CachePlugin {
    static void activate(Engine<CachePlugin, AuditPlugin>& e) {
        e.internal_state_ = 0;
    }
};
```

## Pre-C++26 equivalent

```cpp
// 1. Hand-rolled per friend (drifts out of sync with the type list).
template <typename A, typename B, typename C>
class Engine {
    friend A;
    friend B;
    friend C;
    // …no graceful extension to N plugins…
};

// 2. Access-token pattern.
class Engine {
    struct Key { Key() = default; friend class Owner; };
public:
    void privileged_op(Key) { /* … */ }
};
```

Option 1 hard-codes the arity. Option 2 forces callers to thread a
token through APIs, polluting the public surface for a private concern.

## Gotchas

- The friend pack expansion happens at *class definition* time. If
  the pack expands to zero elements, the result is no friend
  declarations — not an error.
- Combining variadic friends with [[P2662]] pack indexing — e.g.
  "befriend Plugins...[0] only" — is allowed but rarely a clean
  design. Prefer expanding the full pack.
- Variadic-friend declarations participate in name lookup the same way
  ordinary friend declarations do, including the *injected friend* rule
  for ADL. Make sure your namespaces are set up for the expected lookup.
