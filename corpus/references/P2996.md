# P2996 — Reflection for C++26

## Problem
Compile-time introspection over enums, classes, namespaces, and templates
— without resorting to X-macros, hand-maintained switch statements,
external code generators, or third-party libraries like Boost.Describe
and `magic_enum`. Reflection is the headline language addition of
C++26 and unlocks a generation of metaprogramming idioms that no
longer require recursive templates or preprocessor tricks.

## Key syntax

- `^^E` — the *reflection operator*; yields a `std::meta::info` value
  describing the entity `E` (a type, function, value, namespace, …).
- `[: r :]` — the *splicer*; turns a reflection `r` back into the
  named entity (type splice, value splice, template splice).
- `std::meta::*` — the introspection API. Notable functions:
  - `members_of(r)`, `nonstatic_data_members_of(r)`, `enumerators_of(r)`
  - `identifier_of(r)` → returns `std::string_view` (the name)
  - `type_of(r)` → the type a reflection refers to
  - `template_arguments_of(r)` for class-template specialisations
  - `define_static_array(range)` — materialise a constexpr range
    into a static array suitable for `template for` iteration
- Pairs naturally with **expansion statements** (`template for`,
  [[P1306]]) for iterating over reflected sequences.

## Canonical example: enum to string

```cpp
#include <meta>
#include <string_view>
#include <type_traits>

template <typename E>
  requires std::is_enum_v<E>
constexpr std::string_view enum_name(E value) {
    template for (constexpr auto e :
                  std::define_static_array(std::meta::enumerators_of(^^E))) {
        if (value == [: e :]) {
            return std::meta::identifier_of(e);
        }
    }
    return "<unknown>";
}

enum class Color { Red, Green, Blue };
static_assert(enum_name(Color::Green) == "Green");
```

## Canonical example: print all non-static data members

```cpp
#include <meta>
#include <iostream>

template <typename T>
void dump(const T& obj) {
    template for (constexpr auto m :
                  std::define_static_array(
                      std::meta::nonstatic_data_members_of(^^T))) {
        std::cout << std::meta::identifier_of(m)
                  << " = " << obj.[: m :] << '\n';
    }
}

struct Point { int x; int y; };
// dump(Point{3, 4}) prints:
//   x = 3
//   y = 4
```

## Pre-C++26 equivalent

| Need | Pre-C++26 path |
|---|---|
| enum ↔ string | X-macros, Boost.Describe, magic_enum, external codegen |
| struct field iteration | Boost.PFR, manual `std::apply` on `std::tie`, codegen |
| introspect template arguments | `__PRETTY_FUNCTION__` parsing |
| build serialisers / printers | repetitive hand-written switches |

Each of these comes with at least one of: macro hygiene problems, only
works for aggregates, only works up to N members, requires a non-standard
toolchain, or can't operate on private members. P2996 replaces all of
them with one orthogonal mechanism.

## Gotchas

- The header is spelled `<meta>` in P2996R13. Earlier revisions used
  `<experimental/meta>`; references in older code may still mention it.
- `std::meta::info` reflections are *opaque* compile-time values; you
  cannot store them in non-constexpr containers and you can only splice
  them in *constant evaluation* contexts.
- `template for` iterates at compile time — each iteration is a
  separately-instantiated body. Putting non-trivial state (heap
  allocations, non-constexpr `static` variables) inside is usually
  a sign you should split the example.
- Reflection of class layout is *structural*: bitfields and `[[no_unique_address]]`
  members may behave differently from naïve expectations.
- API names continue to evolve between revisions; pin to a known
  revision (`R13` here) when porting examples.
